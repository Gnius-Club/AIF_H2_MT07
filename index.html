🤖 Prompt de Referencia para XOLO (Solo para Maestro)

⚠️ NOTA: XOLO ya conoce el tema de esta misión. Este prompt es SOLO de referencia en caso de emergencia técnica: 
Explícame cómo funciona el ciclo de un módulo HTTP en Make.com: ¿qué significa request, autenticación con API Key, response y parseo de JSON? Muéstrame un ejemplo simple de cómo fluye la información entre estos pasos. Describe el ciclo: 1) Petición (Request): pedimos datos a una URL, 2) Autenticación: nos identificamos con una API Key, 3) Respuesta (Response): recibimos los datos en JSON, y 4) Parseo: los usamos en el workflow.

🚨 Resolución Rápida de Problemas

  • Si los alumnos no pueden ingresar a Gnius Space: Activa XOLO SOS en xolo.gnius.club para continuar la misión sin interrumpir la clase.
  • Si el módulo HTTP da error 401 o 403: Revisar que la API Key sea correcta y que esté colocada en el header o parámetro adecuado.
  • Si el módulo HTTP da error 404: Verificar que la URL de la API esté bien escrita y no tenga espacios extra.
  • Si los datos no se ven en el siguiente módulo: Asegurarse de haber corrido el módulo HTTP al menos una vez para que Make detecte la estructura del JSON (Data mapping).
  • Si hay errores en el código: Recordar a los estudiantes que XOLO puede ayudar a depurar. Pídeles que copien el error y se lo muestren a XOLO.

📊 Diapositiva 3: Brain Spark

1. 💬 Pide a XOLO que te ayude a crear:

"Ayúdame a ser Diplomático Digital: elige conmigo una API pública y define si usaré GET o POST, qué dato enviaré (si aplica) y qué dato recibiré. Guíame a diseñar el escenario con HTTP y a conectar su respuesta a un módulo posterior útil (p. ej. notificar, guardar, transformar). Ejecuta: entrega el blueprint del flujo y un checklist de “conexión correcta” (URL, método, headers, API Key, parseo)."

2. 🔬 Experimenta y descubre con tu programa:

  • ¿La llamada HTTP devuelve el código 200 (éxito) al ejecutar el módulo?
  • ¿Qué sucede si cambias la URL por una incorrecta o escribes mal la API Key?
  • ¿Los datos recibidos en el 'Response' coinciden con la documentación de la API?
  • ¿Cómo ayuda la interoperabilidad a que una empresa pueda usar múltiples herramientas sin perder datos?
  • ¿Qué riesgos de seguridad existen si dejas una API Key expuesta en un repositorio público?

¡Es hora de crear nuestra propia integración! Vamos a convertirnos en Diplomáticos Digitales. El flujo es sencillo: primero idearemos con XOLO qué API queremos usar, luego definiremos el VIBE de nuestra automatización. XOLO nos dará el GCS (la estructura técnica) para configurar nuestro módulo HTTP en Make.com. Por ejemplo, podrían crear un sistema que pida datos de una API de noticias y los envíe a su correo. Recuerden seguir las preguntas de experimentación para asegurar que todo funcione. Si tienen errores o dudas al configurar los headers o el JSON, pregúntenle a XOLO, él los ayudará a depurar.
